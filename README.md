# Бытие — мобильный PWA-пилот

Локальная читалка Быт 1:1–2:3: Синодальный текст, 13 черновиков редакционных разборов, источники и офлайн-сохранение. React, TypeScript, Vite, Vaul (панель на Radix), Phosphor; локальные шрифты Lora и Inter. Название продукта ещё не выбрано.

## Запуск

Нужен Node.js 22.12+.

```sh
npm ci
npm run build
npm run preview
```

Открыть http://127.0.0.1:4173/ и выбрать мобильный размер окна. Для разработки: `npm run dev`. Service worker работает только в собранной версии, чтобы не мешать обновлениям при разработке. Публикация выполняется через ChatGPT Sites; конфигурация проекта — `.openai/hosting.json`.

## Проверка без сети

1. В собранной версии открыть значок скачивания вверху и нажать «Сохранить выпуск».
2. Дождаться сообщения «Выпуск на устройстве».
3. Отключить сеть и перезагрузить страницу.
4. Проверить 34 стиха, пояснения, другое прочтение и библиографию. Внешним сайтам источников нужен интернет.

Статические файлы, шрифты и контент сохраняются как один выпуск. Список файлов и версия формируются при сборке. Новая версия сначала целиком загружается: данные, скрипты и шрифты проверяются по SHA-256, а HTML — по метке выпуска и именам собранных файлов (хостинг может добавлять в страницу свой служебный код). Затем появляется «Доступен новый выпуск». Кнопка «Обновить» переключает все открытые вкладки с сохранением места чтения и размера шрифта. Если загрузка или проверка не удалась, текущий worker и сохранённый выпуск продолжают работать. Для реального телефона нужен HTTPS-адрес: обычный HTTP по LAN не позволяет проверить service worker. На iPhone установка выполняется пользователем из меню Safari; на поддерживаемом Android-браузере доступен системный запрос установки.

Сохранение принадлежит хранилищу браузера: очистка данных сайта или автоматическое освобождение места может удалить выпуск. Проверка статуса заново проверяет наличие всех файлов.

## Контент

- `public/content/genesis.json` — 34 стиха, извлечённые из указанной eBible редакции, с нумерацией и ссылками на источник.
- `public/content/notes.json` — 13 разборов из docs/content/genesis-1-review.md: краткие ответы, авторские аргументы, сопоставления и источники. Все имеют статус `draft`.
- `CONTEXT.md` — согласованный глоссарий, `PRODUCT.md` — границы пилота.

UI-чат не выполняет богословскую редактуру. Следующий пакет готовит контентный чат. Пояснения — редакционные пересказы, не прямые цитаты. Статус цифровой редакции Писания: [eBible · Public Domain](https://ebible.org/russyn/copyright.htm). Авторские права на чужие библиотеки и переводы комментариев этим не подтверждаются.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Браузерным тестам нужен Chromium, установленный для Playwright. Уже установленный совместимый Chromium можно указать через `PLAYWRIGHT_EXECUTABLE_PATH`.

Автотесты проверяют полноту контента, привязки, два пояснения к Быт 1:2, источник и дополнительное прочтение, возврат позиции/фокуса, переход между главами, увеличение шрифта, узкий экран и landscape, reduced motion, ошибки сохранения, отсутствие service worker и офлайн-перезагрузку. Аппаратная проверка iOS/Android и установка на реальный телефон не проведены.

## Визуальные ориентиры

- [NeuBible](https://neubible.co/): сосредоточенное чтение и навигация в пределах большого пальца.
- [BibleProject](https://bibleproject.com/app/): связь фрагмента Писания с подготовленными материалами.
- Mobbin: просмотрены смежные мобильные читалки; точных экранов библейских приложений поиск не вернул.

Из ui-ux-pro-max использованы рекомендации по фокусу, контрасту, касаниям и reduced motion. Автоматические предложения шаблона лендинга и палитры не соответствовали читалке, поэтому не применены. Пользовательское направление — современная тёплая книга — сохранено.

## Публикация и последующее добавление данных

Сайт: https://bible-reading-pilot.nctay.chatgpt.site (доступность подтверждается результатом публикации Sites).

1. Менять подготовленные материалы в `public/content/notes.json`; сохранять источники и статус проверки. Новые вопросы из досье не появляются в приложении, пока не перенесены в этот файл.
2. Запустить `npm test` и `npm run build`. Сборка автоматически вычисляет новую версию по содержимому и worker-коду, а также контрольные суммы данных и ассетов; HTML получает метку этого выпуска. Ручное изменение номера версии и очистка кеша не нужны.
3. Через Sites сохранить и опубликовать новую версию **того же проекта** из `.openai/hosting.json`. Данные в локальной папке сами на хостинг не отправляются. Helper Sites фиксирует и отправляет исходники, затем упаковывает проверенный `dist/`.
4. PWA проверяет обновления при открытии, возврате на экран, восстановлении сети и раз в пять минут, пока экран открыт. Новый выпуск ожидает подтверждения; простое закрытие всех вкладок также позволяет браузеру активировать подготовленную версию. Переключение не требует переустановки приложения.

Проверки обновлений используют два выпуска на отдельном локальном сервере: ожидание подтверждения, две открытые вкладки, позиция и шрифт, новая версия без сети, HTTP-ошибка, повреждённый файл, неверная HTML-версия, добавленная хостингом разметка и успешная повторная загрузка. Первое открытие подготавливает кеш текущей версии в фоне; кнопка сохранения подтверждает, что выпуск целиком доступен на устройстве. Хранилище браузера может быть очищено самим браузером или пользователем.
